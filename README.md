# 쉬어갈곳 — 무료 휴식공간 찾기 MVP

현재 위치나 주소를 기준으로 벤치·정자 같은 확인된 착석 시설과 공원·쉼터 같은 휴식 가능 장소를 지도와 목록으로 보여주는 반응형 웹 MVP입니다. 지도는 Leaflet + OpenStreetMap, 주변 장소 데이터는 Overpass를 사용합니다. 국내 공공데이터 provider 어댑터 구조는 마련되어 있으며 데이터셋을 등록하면 OSM 누락을 보완할 수 있습니다.

## 실행 및 TMAP App Key 설정

브라우저는 같은 출처의 `/api/tmap/pedestrian`에 경로 요청을 보내고, `server.js`가 서버의 `TMAP_APP_KEY` 환경변수로 TMAP 요청을 전달합니다. 키는 프런트엔드에 보내지 않습니다.

프로젝트 루트에 `.env` 파일을 만들고 다음 값을 설정합니다.

```dotenv
TMAP_APP_KEY=발급받은_App_Key
```

실제 발급 키만 `.env`에 넣고, `.env`는 Git 및 배포/제출 ZIP에 포함하지 마세요. 의존성이 설치되어 있지 않다면 설치 후 서버를 실행합니다.

```sh
npm install
node server.js
```

`http://127.0.0.1:3000`에 접속합니다. 현재 위치 기능은 HTTPS 또는 localhost와 브라우저 위치 권한이 필요합니다. 배포에서는 Node.js 서버를 실행하는 호스팅의 비밀 환경변수에 `TMAP_APP_KEY`를 등록해야 합니다.

## OSM 후보 검색과 표시

- `amenity=bench`, `bench=yes`, `leisure=gazebo` 등은 **확실한 착석 공간**으로 분류합니다. 좌석 정보가 없는 일반 `leisure=park`, `landuse=recreation_ground` 공원도 별도 Overpass 검색하여 결과에 남깁니다.
- 결과 목록은 **확실한 착석 공간**과 **휴식 가능 장소 · 착석시설 정보 확인 필요**로 나눕니다. 공원은 `공원 · 착석시설 정보 확인 필요`로 표시하며, 공원 영역 중심 마커가 개별 벤치 좌표를 뜻하지 않는다는 점도 상세에 표시합니다.
- 반경 1km, 1.5km, 2km에서 착석시설, 공원, 보완 휴식 후보를 별도로 검색합니다. 벤치 결과 수만으로 공원 조회를 생략하거나 검색을 조기 종료하지 않습니다.
- OSM에서 `fee`/`charge`가 명시적으로 유료이거나 `access=private/no/customers`인 후보는 제외합니다. 태그가 없다는 사실은 무료·개방이 검증되었다는 뜻이 아닙니다.
- Overpass 서버가 혼잡할 때 다른 공개 인스턴스를 재시도합니다. 일부 결과를 확보한 뒤 추가 검색이 실패하면 확보 결과를 유지합니다.

## 국내 공공데이터 provider 어댑터

`js/public-data.js`에 provider를 등록하면 OSM과 같이 검색할 수 있습니다. 예시:

```js
Data.registerPublicPlaceProvider({
  id: 'provider-name',
  source: '데이터 제공기관/데이터셋명',
  async fetch({ lat, lng, radiusMeters, coordinateSystem }) {
    // 원본 API/파일을 조회해 레코드 배열 반환
    return [];
  },
  normalize(record) {
    // 좌표계를 WGS84로 변환하고 표준 장소 객체 반환 (좌표 속성 순서: lat, lng)
    return {
      id: 'provider-record-id',
      name: '장소명',
      type: '공원',
      category: 'park',
      lat: 37.0,
      lng: 127.0,
      resultGroup: 'possible', // 착석 근거가 명시된 경우에만 'confirmed'
      details: { seating: '착석시설 정보 확인 필요' }
    };
  }
});
```

원본 데이터의 좌표계·필드, API 약관, 출처 표시 의무와 CORS를 확인한 뒤 provider를 등록해야 합니다. provider의 `normalize()`가 TM 좌표계 등을 WGS84 위도·경도로 변환합니다. 현재 코드에는 공공 provider 확장 구조만 있으며 실제 국내 데이터셋은 아직 등록되어 있지 않습니다.

OSM ID가 같은 항목은 병합합니다. 출처가 다르면 40m 이내이면서 정규화한 장소명이 같거나 4자 이상으로 충분히 구체적인 이름이 포함 일치할 때 중복 처리합니다. 병합된 장소는 모든 출처를 보존하고, 확인된 좌석 시설 데이터가 공원 후보와 병합될 때는 착석 확정 분류를 유지합니다.

## TMAP 도보 길찾기

1. 직선거리는 가까운 후보를 1차로 추리는 내부 계산에만 사용하고 화면에는 표시하지 않습니다.
2. 가까운 후보 최대 12곳에 대해 TMAP 보행 경로를 요청합니다. 그 외 후보도 결과와 지도에 남기고, 사용자가 선택하면 그 목적지의 경로를 요청합니다.
3. 목록에는 TMAP 보행 경로 거리·예상시간만 표시합니다. 요청 실패 시 `도보 경로를 불러오지 못했습니다`로 구분하고 직선거리로 대체하지 않습니다.
4. 장소를 선택하면 TMAP 경로선을 Leaflet 지도에 그리고, 응답에 단계 안내가 있으면 표시합니다. 안내 시작은 브라우저 GPS를 사용하는 MVP 기능입니다.

TMAP 경로는 데이터 기반 예상치이며 현장 통행 가능성이나 실시간 상황을 보장하지 않습니다. 앱 안내는 상용 내비게이션이 아니며 음성 안내·화면이 꺼진 상태의 백그라운드 추적을 제공하지 않습니다.

## 데이터 한계 및 휴대폰 확인

- OSM 등록 여부와 데이터 완전성은 지역마다 다릅니다. 실제 공원이 OSM에 없거나 다른 태그로 입력되어 있다면 검색되지 않을 수 있습니다. 공공데이터 provider를 등록하면 누락을 보완할 수 있습니다.
- 공원 폴리곤은 공원 영역 중심을 대표 좌표로 쓰며 입구나 벤치 위치가 아닐 수 있습니다. 착석 상태·무료 이용·현재 개방 여부는 보장하지 않습니다.
- 주소 검색에는 Nominatim 공개 서비스를 사용하므로 호출 정책을 준수합니다. OSM은 ODbL 및 출처 표시 조건을 따릅니다.
- 휴대폰에서 현재 위치 사용 후 주변 공원이 결과에 뜨는지, 목록의 휴식 가능 장소 그룹과 지도 마커가 맞는지 확인해 주세요. 이 작업 환경에서 실제 Overpass 응답과 모바일 브라우저는 실행 확인하지 않았습니다.
